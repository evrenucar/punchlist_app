## Overall assessment

Nothing is fundamentally wrong with the repository structure. For Punchlist's stated goal, a local-first application distributed as one directly openable HTML file, the separation between `src/`, build scripts, generated output, website files, documentation and tests is sensible. The project explicitly treats the one-file, no-server, no-framework design as a core product constraint, so moving to React, a backend, or a conventional multi-file web application would likely make it worse rather than better.

The main issue is:

> The diagram looks modular, but most of the runtime architecture is physically one JavaScript file.

`src/task-board.js` already exceeds 7,000 lines and contains global state, DOM references, editing, task lifecycle, rendering, planning, persistence, GitHub sync, identity, import/export, focus mode and responsive behaviour.

## 1. Build during deployment

The Pages workflow uploads the existing `website/` directory without running the builder or the test suite, so someone can change `src/task-board.js`, forget to build, push, and successfully deploy an outdated application.

Recommended: `setup-node`, then `node scripts/build-task-board.mjs`, then `node --test tests/task-board.static.test.mjs`, then configure/upload/deploy. For pull requests, add a generated-file consistency check: rebuild, test, then `git diff --exit-code -- outputs website/task-board.html website/index.html`.

## 2. Split the source without changing the final one-file product

No framework, no bundler. Split the development source into ordinary JavaScript files concatenated by the existing build, in a fixed order: `constants, state, migrations, task-tree, lifecycle, persistence, github-sync, identity, import-export, editor, planning, focus, rendering, interactions, app`. Same for CSS. The generated `outputs/task-board.html` stays exactly one offline file.

Extract in this order, lowest risk first: migrations and state normalization, task-tree operations, lifecycle and retention rules, sync-decision logic, import/export and identity. Rendering and interaction last. Do not start with drag-and-drop or contenteditable, they are the most browser-coupled sections.

## 3. Add actual browser testing

The Node-VM harness with a hand-written mock DOM is useful for pure logic and output contracts, but cannot represent contenteditable, selection and caret behaviour, `<details>` visibility, drag and drop, pointer events, touch, storage behaviour, resize and responsive transitions, or real focus. The project's own notes record a test that passed while the feature was broken because the mocked visibility model differed from Chrome.

Minimum Playwright suite: open the built app; create and edit a task; create a nested task; complete a task; reload and confirm persistence; export and reimport JSON; sidebar at desktop and mobile widths; open and close the mobile drawer then resize above 980px; a contenteditable Enter/split; and GitHub sync decisions against a mocked fetch.

Structure: keep `task-board.static.test.mjs`, add `task-board.browser.test.mjs`.

## 4. Decouple update checking from GitHub Releases

The local copy checks GitHub's latest Release to decide whether an update exists. The project history records approximately 24 builds deployed while the latest Release stayed old, so existing clients were never notified.

Generate `website/latest.json` (`version`, `download`, `notes`) on every build and have local copies check that instead. Two separate concepts afterwards: latest deployed build (`latest.json`) versus stable downloadable milestone (GitHub Release).

## Recommended final direction

Do not rebuild the application architecture from scratch. Keep vanilla HTML/CSS/JavaScript, no required server, one distributable HTML file, LocalStorage as the default, GitHub sync as optional, and the simple Node build script.

Strongest next batch: make Pages build and test from `src/`; add a small real-browser CI suite; generate `latest.json` for update checking; gradually split `task-board.js` into concatenated source modules.
